§1

DNS nima? — Telefon kitobi analogiyasiWhat is DNS? — the phone-book analogy

DNS (Domain Name System) — internetning telefon kitobi. Odamlar nomlarni eslab qolishadi (google.com), lekin kompyuterlar bir-biriga faqat IP manzillar orqali murojaat qiladi (142.250.187.206). DNS nomni IP ga aylantiradi — bu jarayon «resolution» (hal qilish) deyiladi. DNS (Domain Name System) is the internet's phone book. People remember names (google.com), but computers only address each other by IP (142.250.187.206). DNS translates a name into an IP — a process called «resolution».

Deyarli har bir internet amaliyoti — sayt ochish, email yuborish, ilova ulanishi — DNS so'rovidan boshlanadi. Agar DNS ishlamasa, internet «ishlamaydi» ga o'xshaydi, garchi serverlar tirik bo'lsa ham: siz raqamni bilmaysiz, faqat ismni bilasiz. Almost every internet action — opening a site, sending mail, an app connecting — starts with a DNS query. If DNS breaks, the internet "feels down" even while servers are alive: you know the name, not the number.

Asosiy g'oya: DNS markazlashmagan, daraxt shaklidagi, keshlanadigan tizim. Hech bir server hamma javobni bilmaydi — har biri faqat keyingi qadamni ko'rsatadi. Core idea: DNS is a decentralized, tree-shaped, cached system. No single server knows every answer — each only points to the next step.

§3

Ierarxiya: Root → TLD → AuthoritativeThe hierarchy: Root → TLD → Authoritative

DNS teskari daraxt: yuqorida ildiz (root), pastda alohida domenlar. Har daraja faqat keyingi darajani biladi — bu tizimni miqyoslanuvchi va chidamli qiladi. DNS is an inverted tree: the root at the top, individual domains at the bottom. Each level only knows the next — which makes the system scalable and resilient.

Recursive vs iterative: the client asks the resolver recursively ("get me the full answer"). The resolver then works iteratively with Root→TLD→Authoritative (asking each "who's next?").

§5

Keshlash va TTL — nega ikkinchi so'rov tez?Caching and TTL — why is the second query fast?

Har bir javob TTL (Time To Live) bilan keladi — necha soniya saqlash mumkinligini bildiradi. Resolver (va sizning brauzeringiz, OS) javobni shu muddatga keshlaydi. Shuning uchun birinchi so'rov butun zanjirni yuradi, ikkinchi so'rov esa to'g'ridan-to'g'ri keshdan keladi — millisekundlarda. Every answer comes with a TTL (Time To Live) — how many seconds it may be stored. The resolver (and your browser, OS) cache the answer for that long. So the first query walks the whole chain, while the second comes straight from cache — in milliseconds.

Katta TTL = tezroq va serverga kam yuk, lekin o'zgarish sekin tarqaladi. Kichik TTL = tez yangilanish (masalan migratsiya oldidan), lekin ko'proq so'rov. Migratsiyadan oldin TTL ni pasaytirish — klassik amaliyot. High TTL = faster and less server load, but changes propagate slowly. Low TTL = quick updates (e.g. before a migration), but more queries. Lowering the TTL before a migration is a classic move.
§6

DNS xavfsizligiDNS security

DNS dastlab ishonchga qurilgan va shifrlanmagan edi — shuning uchun bir nechta hujum turi bor:DNS was originally built on trust and unencrypted — hence several attack classes:

Cache poisoning / spoofingCache poisoning / spoofing

Hujumchi resolver keshiga soxta javob «tiqadi» — foydalanuvchini soxta IP ga (fishing sayti) yo'naltiradi. Klassik Kaminsky hujumi shu zaiflikni ochgan.An attacker injects a forged answer into the resolver's cache — redirecting the user to a fake IP (a phishing site). The classic Kaminsky attack exposed this.

DNSSEC

Yozuvlarni raqamli imzo bilan tasdiqlaydi (RRSIG). Resolver imzoni tekshirib, javob soxtalashtirilmaganiga ishonch hosil qiladi. Maxfiylikni emas — yaxlitlikni himoya qiladi.Signs records cryptographically (RRSIG). The resolver validates the signature to trust the answer wasn't forged. Protects integrity, not privacy.

DoH / DoT

DNS over HTTPS (DoH) va DNS over TLS (DoT) — DNS so'rovlarini shifrlaydi, shu bilan tarmoqdagi kuzatuvchi qaysi saytlarga kirayotganingizni ko'ra olmaydi. Bu maxfiylikni himoya qiladi.DNS over HTTPS (DoH) and DNS over TLS (DoT) encrypt DNS queries, so an on-path observer can't see which sites you visit. This protects privacy.

DNS amplifikatsiya (DDoS): hujumchi kichik so'rovni qurbon IP nomidan (soxtalashtirilgan manba) ochiq resolverga yuboradi; resolver katta javobni qurbonga qaytaradi. Kichik so'rov → katta javob = kuchaytirish. Ochiq rekursiv resolverlar shuning uchun xavfli. DNS amplification (DDoS): the attacker sends a small query with a spoofed source (the victim's IP) to an open resolver; the resolver sends a large answer to the victim. Small query → big answer = amplification. This is why open recursive resolvers are dangerous.
§7

Amaliyot: dig, nslookup, hostPractice: dig, nslookup, host

dig +trace butun ierarxiyani (Root → TLD → Authoritative) qadam-baqadam ko'rsatadi — simulyatordagi jarayonni haqiqiy buyruqda ko'rasiz.dig +trace shows the whole hierarchy (Root → TLD → Authoritative) step by step — the simulator's process as a real command.

bash — dig
$ dig example.com A +short
# 93.184.216.34

$ dig example.com MX +short
# 10 mail.example.com.

$ dig +trace example.com
.            IN NS  a.root-servers.net.        ← Root
com.         IN NS  a.gtld-servers.net.        ← TLD (.com)
example.com. IN NS  a.iana-servers.net.        ← Authoritative
example.com. IN A   93.184.216.34              ← final answer
bash — nslookup / host
$ nslookup example.com
Server:  1.1.1.1
Address: 93.184.216.34

$ nslookup -type=MX example.com
# example.com  mail exchanger = 10 mail.example.com.

$ host -a example.com
# example.com has address 93.184.216.34
# example.com mail is handled by 10 mail.example.com.
Maslahat: keshni chetlab o'tib to'g'ridan-to'g'ri authoritative serverdan so'rash uchun dig @ns1.example.com example.com. TTL ni ko'rish uchun +short siz oddiy dig ni ishlating — javobdagi ikkinchi ustun TTL. Tip: to bypass cache and ask the authoritative server directly, dig @ns1.example.com example.com. To see the TTL, run plain dig without +short — the second column of the answer is the TTL.

Root DNS server so'rovga qanday javob beradi?How does a Root DNS server respond to a query?
To'g'ri: Root server yakuniy javobni bilmaydi — u faqat tegishli TLD (masalan .com) serverlarining manzilini ko'rsatadi (referral).
